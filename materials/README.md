# Материалы для наполнения портала

Здесь лежат исходники контента. Из этой папки контент уезжает в Supabase одной командой —
без Excel и без ручной загрузки через Table Editor.

## Как устроено

```
materials/
├── disciplines.json          # список дисциплин и псевдонимы id
├── _example/                 # образец: как выглядит готовый набор
│   └── content/
│       ├── articles.json
│       ├── tickets.json
│       ├── flashcards.json
│       ├── tests.json
│       ├── practice.json
│       └── library.json
├── _current/                 # выгрузка текущего контента из базы (для правок)
└── <дисциплина>/             # например, general-psych
    ├── inbox/                # сюда кидаешь что есть: docx, pdf, txt, фото конспектов
    └── content/              # отсюда импорт: те же файлы
        ├── articles.json
        ├── tickets.json
        ├── flashcards.json
        ├── tests.json
        ├── practice.json
        └── library.json
```

`inbox/` — для тебя: складывай что угодно, я разберу и превращу в `content/`.
`content/` — машинный формат: только JSON, его читает импорт.

`_current/` — снимок того, что сейчас в базе: 67 статей, 98 билетов, 177 карточек, 140 тестов,
20 книг. Его можно править и импортировать обратно — обновится то же самое, дублей не будет.

## Форматы

Все файлы — массив объектов. `discipline_id` можно не писать в каждом объекте:
он берётся из папки (или из поля `discipline_id` в начале файла, если это один общий JSON).

### articles.json — статьи-лонгриды

```json
[
  {
    "discipline_id": "general-psych",
    "title": "1. Психика и её свойства",
    "content": "<p>Текст статьи. Можно HTML: <strong>жирный</strong>, списки, заголовки h3.</p>",
    "source": "Гиппенрейтер Ю.Б. Введение в общую психологию, гл. 2"
  }
]
```

Обязательны `title` и `content`. `source` — откуда взято, попадает в служебное поле и в отчёт.

### tickets.json — экзаменационные билеты

```json
[
  {
    "discipline_id": "general-psych",
    "number": "1",
    "title": "Понятие психики. Функции и свойства психики",
    "recommend_time": "15–20 минут",
    "plan": "1. Определение психики\\n2. Функции\\n3. Свойства",
    "content": "<p>Конспект ответа.</p>",
    "books": ["Гиппенрейтер Ю.Б. — Введение в общую психологию"]
  }
]
```

`books` — необязательный список книг в формате `Автор — Название`. Книга должна уже быть
в `library.json`, иначе импорт остановится и скажет, какой книги не хватает.

### flashcards.json — карточки терминов

```json
[
  { "discipline_id": "general-psych", "term": "Психика", "definition": "Свойство высокоорганизованной материи..." }
]
```

### tests.json — вопросы тестов

```json
[
  {
    "discipline_id": "general-psych",
    "question": "Что изучает общая психология?",
    "options": ["Закономерности психики", "Общество", "Культуру", "Экономику"],
    "correct_index": 0,
    "link_url": "tickets.html"
  }
]
```

`options` — от 2 до 6 вариантов, `correct_index` — номер правильного с нуля.
`link_url` — необязательная относительная ссылка на материал.

### practice.json — задания «Практикума»

Задания верхних уровней таксономии Блума (`apply`, `analyze`, `evaluate`, `create`)
с самопроверкой по критериям. Это не тесты на узнавание: задача даёт ситуацию, действие,
критерии и эталон. Полный контракт — `docs/SPEC-PRACTICE.md`.

```json
[
  {
    "discipline_id": "general-psych",
    "slug": "apply-memory-complaint",
    "level": "apply",
    "competence": "применение психологических знаний в практической задаче",
    "title": "Жалоба на «плохую память»: что проверять первым",
    "situation": "<p>Студентка жалуется на плохую память и просит совета, как готовиться.</p>",
    "task": "<p>Какое учебное действие проверить в первую очередь?</p>",
    "kind": "choice",
    "options": ["Скорость чтения", "Отсроченное воспроизведение", "Объём кратковременной памяти"],
    "correct_index": 1,
    "criteria": ["Выбран вариант с отсроченным воспроизведением", "Объяснено отличие от объёма памяти", "Учтена стратегия подготовки"],
    "model_answer": "<p>Эталонный ответ, который допускает альтернативные формулировки.</p>",
    "explanation": "<p>Почему верный вариант верен, а остальные нет.</p>",
    "source": "Общая психология: тема «Память» (материалы портала)",
    "ai_generated": true,
    "active": true,
    "sort_order": 10
  }
]
```

- `kind`: `choice` или `open`. Для `open` — `options` и `correct_index` равны `null`,
  `model_answer` обязателен, `explanation` может быть `null`.
- `level`: `remember|understand|apply|analyze|evaluate|create`; в пилоте — только
  верхние четыре.
- `criteria` — 3–5 наблюдаемых признаков по 10–300 символов.
- `slug` уникален внутри дисциплины: `^[a-z0-9-]{3,64}$`, по нему идёт повторный импорт.
- `source` — реальный раздел/учебник или тема портала, до 500 символов.
- `active: false` скрывает задачу со страницы, не удаляя попытки.

### library.json — каталог литературы

```json
[
  {
    "title": "Введение в общую психологию",
    "author": "Гиппенрейтер Ю.Б.",
    "annotation": "Классический учебник: предмет психологии, психика, сознание, деятельность."
  }
]
```

## Команды

```powershell
# Проверка без записи в базу: что добавится, что обновится, где ошибки
node scripts/content-import.mjs materials/general-psych

# Записать в Supabase (нужен .env с service_role)
node scripts/content-import.mjs materials/general-psych --apply

# Выгрузить текущий контент из базы обратно в JSON (для правок)
node scripts/content-import.mjs --export materials/general-psych/content

# Отчёт по «Практикуму»: задачи, попытки, самопроверка (только чтение)
node scripts/practice-report.mjs
node scripts/practice-report.mjs --json
```

Выгрузка включает `practice.json`; служебные `id`, `created_at`, `updated_at` при экспорте
удаляются, чтобы файл можно было импортировать обратно.

Импорт идемпотентный: повторный запуск обновляет существующие записи по естественному ключу
и не создаёт дублей. Версия контента в `version_control` поднимается триггерами автоматически —
пользователи увидят новое после перезагрузки страницы.

## Как docx превращается в билеты

Если экзаменационный файл свёрстан вопросами-заголовками (стиль Heading 1/2) и ответами под ними,
он превращается в `tickets.json` одной командой:

```powershell
python scripts/docx_tickets.py --input "inbox/.../Экзамен.docx" --out materials/<дисциплина>/content/tickets.json --start 1
```

Конвертер берёт каждый заголовок за вопрос, всё до следующего заголовка — за ответ, абзацы
и списки размечает в HTML. Файлы без заголовков (просто нумерованные абзацы) так не разбираются —
для них нужен ручной разбор.

Привести конспекты к стилю сайта (заголовок вопроса, подзаголовки, жирные термины, перечни):

```powershell
python scripts/format_tickets.py materials/<дисциплина>/content/tickets.json
```

## Плашка «контент сгенерирован ИИ»

В `articles`, `tickets` и `practice` есть поле `ai_generated`. Поставь `true`, если материал
больше чем наполовину написан моделью, а не тобой и не из твоих конспектов. На странице
появится красная плашка с просьбой проверять факты.

```json
{ "discipline_id": "general-psych", "title": "...", "content": "...", "ai_generated": true }
```

## Правила, которые проверяет импорт

- дисциплина есть в `disciplines.json` (или в её псевдонимах);
- обязательные поля заполнены, длины в разумных пределах;
- в тестах 2–6 вариантов и `correct_index` указывает на существующий;
- в заданиях практикума `criteria` — 3–5 строк, `choice` требует `options`/`correct_index`/
  `explanation`, `open` требует `model_answer` и запрещает `options`/`correct_index`;
- внутри одного файла нет повторов по ключу;
- в HTML нет `<script>` и inline-обработчиков `onclick=`;
- книги из `books` существуют в `library.json`.
