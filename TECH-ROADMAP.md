## 1. Правила работы (обязательны для любого чата)

1. **Перед изменениями:** `git status`, `git log --oneline -5`, прочитать `TECHCARD.md` и этот файл. Незакоммиченные чужие правки не перезаписывать.
2. **Один этап — один коммит.** Сообщение в стиле `fix(ui): …`, `perf(data): …`, `chore(deploy): …`.
3. **Секреты только в `.env`** (gitignored). Не коммитить PAT, service_role, `.mcp.json`. Токен в коде/логах/скриншотах — ошибка.
4. **Перед любой миграцией БД** — `node scripts/backup-db.mjs`; SQL выполнять через `node scripts/db-exec.mjs file.sql`, сначала с `--dry-run`.
5. **Не открывать анонимную запись в контентные таблицы.** Новые записи — только через RPC/Edge Function с валидацией.
6. **При изменении любого файла из `sw.js` ASSETS** поднять `CACHE_NAME` (`psy-hub-v21` → `v22`), иначе пользователи останутся на старом кэше.
7. **Пути только относительные** (`js/...`, `sw.js`), без ведущего `/`: сайт живёт в подпапке `/psychology-portal/`. Исключения — только там, где протокол требует абсолютный URL: `canonical`, `og:image`/`og:url`, `sitemap.xml`, ссылка на главную в `404.html`.
8. **Проверять на 1440, 1024, 768, 390 px.** Критерий: `document.documentElement.scrollWidth === innerWidth`, контент виден, в консоли нет ошибок.
9. **Не использовать Vercel для проверки из РФ** — он обрывает TLS. Проверять GitHub Pages или локальный сервер.
10. **PowerShell 5.1 и кириллица:** никогда не перезаписывать файлы через `Get-Content … | Set-Content` — получите двойную перекодировку. Правки — только через `edit`/`write` либо Node с `utf8`. Если файл уже испорчен — восстановить из git.
11. **Не переписывать архитектуру «на фреймворке»** без отдельного решения: текущий статический сайт намеренно без сборки.
