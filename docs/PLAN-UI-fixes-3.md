## 1. Главная находка: трекер ломал страницу при загрузке из кэша

Три пункта документа («не отображается навигация билетов», «не работает поиск», «закладки не отображаются теперь совсем») — один и тот же сбой.

**Что происходило.** На повторном визите страница рисуется из `localStorage`-кэша синхронно, внутри первого обработчика `DOMContentLoaded`. `initTickets` сразу открывает первую дисциплину → `PsyTracker.event('ticket_open')` → `push()` → `touchSession()`. Трекер инициализируется своим обработчиком `DOMContentLoaded`, который стоит **вторым**, поэтому `session` ещё `null` — и `touchSession` падал с `TypeError: Cannot set properties of null`.

Исключение обрывало `initTickets` **до** создания плиток, привязки поиска и рендера панели закладок. Отсюда: пустая страница с заглушкой, мёртвый поиск и пропавшие закладки — при этом на «первом» визите без кэша всё работало. Это и объясняет, почему баги казались плавающими.

**Что сделано.**

- `js/tracker.js`: `touchSession()` создаёт сессию, если её ещё нет; `push()` и `flush()` полностью обёрнуты в `try/catch` — журнал больше не может уронить страницу; `flush` при сбое возвращает события в очередь.
- `js/tickets.js`, `js/sections-wiki.js`: вызовы `PsyTracker.event` дополнительно обёрнуты — даже сбойный трекер не остановит навигацию.
- Регрессия: сценарий `layout` теперь идёт перед `bookmarks`/`search`/`mobileNav` и создаёт кэш, то есть проверяет именно повторный визит. До фикса эти три сценария падали — после проходят.
