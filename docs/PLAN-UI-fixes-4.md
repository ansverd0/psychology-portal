## 1. Главная находка: подвал был вплотную к контенту

Пять пунктов документа — «такая же проблема с подвалом» на `cards`, `tickets`,
`sections`, мобильных версиях — это один и тот же дефект: **тёмная плашка
начиналась ровно там, где заканчивался контент, без зазора**. На главной это
видно буквально: `footer.top === menu-grid.bottom` (589 px и 589 px), на
`cards` — `controls.bottom === footer.top`.

Как закрыто: у подвала появилась светлая полоса-зазор, сделанная так, чтобы не
ломать прижатие к низу коротких страниц:

```css
.site-footer {
    border-top: 25px solid transparent;  /* 20px на телефоне */
    background-clip: padding-box;        /* фон не заходит под прозрачную рамку */
}
```

`margin-top: auto` остаётся рабочим: на короткой странице подвал по-прежнему
упирается в нижний край экрана, а на длинной между контентом и тёмной плашкой
всегда 25 px (на телефоне 20 px). Никаких пустых `<div>` в 12 HTML-файлов.

**Второе замечание про подвал** («немного опустить, чтобы „Главное меню“ было
ближе к нижнему краю, но не лежало на нём») — нижний отступ подвала уменьшен
на 14 px: `padding: 40px 0 20px` → `40px 0 6px`, на телефоне `28px 0 18px` →
`28px 0 4px`. Текст ссылки теперь в 20 px от нижнего края (было ~35), на
телефоне — 22 px (было ~32).

Попутно нашлась ошибка каскада: медиазапрос «до 1600 px — копирайт и навигация
столбиком» стоял **выше** базового правила `.site-footer__bottom`, поэтому
`align-items: flex-start` перебивался базовым `center` — на 1024–1599 px
копирайт и ссылки выстраивались по центру подвала. Правило перенесено после
базового: на 1440 копирайт и навигация снова от левого края, на ≥1600 —
прежняя строка «копирайт слева, ссылки справа».

## 3. Кнопка закладок над подвалом

Замечание «такая же проблема с кнопкой закладок» было про то, что звезда
ложилась поверх подвала. Высота считается в CSS, JS только подставляет значение:

```css
.bookmarks-fab { bottom: calc(80px + var(--fab-lift, 0px) + env(safe-area-inset-bottom)); }
```

`updateBookmarksFabLift()` в `js/supabase-config.js` на `scroll`/`resize` (через
`requestAnimationFrame`) поднимает кнопку на высоту видимой части подвала + 12 px.
Пока подвал на экране — звезда над ним, зазор не меньше 12 px.

Кнопка «наверх» подъём **не** использует: по правке автора механика только для
закладок, стрелка всегда стоит в 16 px от нижнего края.

## 4. Проверка

`npm run check:ui` — **91/91**, 11 сценариев (было 72/9):

- `layout` (22) — ширины 1024–1920 (конспект 501/708/868/920 px), плитки, шапка
  с ID, `sections` с подписью и короткой инструкцией (вместо старой проверки
  «в шапке нет инструкции»), ширина 2-й колонки ≥ 220 px, прокрут 16 px,
  выключка по ширине на телефоне;
- `bookmarks` (8), `search` (6), `mobileNav` (6) — без изменений;
- `diag` (5), `surveyHang` (4), `offline` (7) — без изменений;
- `footer` (19) — тёмный подвал, прижатие к низу, **зазор ≥ 18 px на четырёх
  страницах**, **«Главное меню» в 12–30 px от края**, **звезда закладок над
  подвалом, «наверх» у нижнего края**, кнопка закладок у поиска, отсутствие
  перекрытия навигации;
- `wiki` (4) — новый сценарий: карточка не обрезает подсказку, подсказка
  раскрывается при наведении, горизонтальной прокрутки нет;
- `surveyGroups` (3) — новый сценарий: три направления, порядок `821, 831, 841`,
  9 групп + пустой пункт;
- `visual` — скриншоты 390/1440 и низ страниц.

Ручные замеры (Chrome, headless, локальный сервер) — `footer.top` в документе:
`index` 589 → 614 (плитка кончается на 589), `cards` `controls.bottom` 589 →
тёмная плашка 614, `tickets`/`sections` — то же; `sections-1440` при наведении
на термин «бихевиоризм» подсказка рисуется от 490 px, хотя карточка начинается
с 517 px (раньше обрезалась по 517).

`js/sections-wiki.js`, `js/survey.js`, `js/survey-data.js`, `sections.html`,
