## 1. Диагноз: три причины, а не 88 находок

**1. Дизайн-системы нет — её никогда не было.** В `style.css` 3759 строк, 507 правил и **одна** своя переменная (`--fab-lift`, строка 1421); `:root` отсутствует. 53 цвета, 20 кеглей, 29 значений `box-shadow`, 38 медиазапросов, 13 вариантов кнопок. `h1–h6` и `a` не описаны вовсе — работают браузерные умолчания, поэтому `h4` = 16 px = основному тексту, лозунг `h2` = 24 px = заголовку билета, а на `cards` термин 26 px крупнее заголовка раздела. Каждая страница живёт в своей сетке: `main` 520–1400 px, левый край `h1` 20–523 px.

**2. Шапка и мера строки — главный визуальный провал, а не цвет и тени.** На 390 шапка занимает 42–50 % экрана (417 px на `tickets`), из них 128–160 px — рекламный `h2` в 24 px. Внутри конспекта строка 103–105 знаков при `text-align: justify`; на `news@390` — 32 знака и провалы между словами до 40 px. Планшет 768 получает меру ПК (90 знаков при телефонной раскладке).

**3. Сценарий подготовки не собран.** Главная не отвечает «что я учу» и не показывает 27 дисциплин (11 из них пусты и об этом нигде не сказано). Практикум после ответа оставляет экран без кнопки «дальше» (`nextTop` −648 на 1366 и −912 на 360), адреса у задания нет (Back → главная, F5 → список), у гостя «Пройдено 0 из 4» после решённого задания. Поиск ищет подстроку в заголовке: «психика» → 0 при 168 билетах. 221 из 432 «Повторить тему» ведут на несуществующий `articles.html`. Восемь инструментов не связаны: из билета нельзя перейти к статье, книге или термину.

**Отсюда порядок работ** — по воронке студента, а не по документам:
**экран → действие → выбор → система → память → контент**.

## 2. Правила игры

1. **ID работы — `UI2-xx`.** Префиксы аудитов (`U-`, `H-`, `S-`, `P-`) остаются **ссылками на доказательства**, а не номерами задач: `U-01…U-09` уже заняты закрытым пакетом «UX/SEO» в `TECH-ROADMAP`, `S-01…S-12` — блоком безопасности. Новая нумерация снимает коллизию, из-за которой новый чат неизбежно перепутал бы задачи.
2. **Один спринт — один чат.** Внутри спринта — коммит на задачу, пуш в конце спринта. Закрытие — `handoff.py`, как принято в проекте.
3. **Статика без сборщика.** Никаких фреймворков, npm-зависимостей и CDN. `npm` в PowerShell заблокирован — запускать `node scripts/…`.
4. **Контент, БД и `scripts/check-*.mjs` в CSS-спринтах не трогаем.** Миграции — только с бэкапом и `--dry-run`.
5. **Правка любого файла из `sw.js` ASSETS → `CACHE_NAME` +1** (`v35` → `v36` → …). Проверка после пуша: Pages отдаёт новую версию.
6. **Сырых значений в CSS не добавляем.** После `UI2-01` новый цвет, кегль, отступ, радиус и тень — только через токен.
7. **`node scripts/ui-probe.mjs` зелёный после каждого спринта** (14 сценариев, 157 проверок). Плюс снимки 390/768/1024/1440 до и после.
8. **Кириллицу не перезаписывать через `Get-Content | Set-Content`** — только `edit`/`write`/Node с `utf8`.
9. **Не называть новые документы `roadmap*.md`** — этот шаблон в `.gitignore` (личные черновики ВКР), файл молча не попадёт в коммит. Поэтому план называется `PLAN-UI-…`, как `PLAN-LIBRARY` и `PLAN-RESEARCH`.

### Спорные места и принятые решения

| Спор | Решение | Почему |
|---|---|---|
| Высота шапки: 56 px (`.topbar`) или ≤ 120 px (UI-REDESIGN) | 56 + `.page-head` ≈ 112–120; метрика — высота всего блока `header` | 120 — то, что мерил аудит (`header.h`), иначе сравнивать не с чем |
| `h1` 24/600 (U-01) или 24/700 (токены) | 24/700 | 600 в проекте нигде не используется как заголовочный вес |
| `h2` 22 px (U-05) при шкале 12/13/14/16/18/20/24/32 | 20 — раздел, 24 — заголовок билета/статьи | Не вводить девятый кегль ради одного правила |
| `justify`: убрать везде или только при мере < 60 знаков | убрать везде | Статический учебный текст; выигрыша от выключки нет ни на одной ширине |
| Счётчики дисциплин: REST или сборка | сборка: `scripts/build-disciplines.mjs` → `js/disciplines-stats.js` из `materials/*/content/*.json` | Главная по проекту не грузит таблицы (P-02); REST на первом экране убил бы первый рендер и офлайн |
| Прогресс гостя: localStorage или RPC | localStorage; в БД только с ID | Иначе меняется семантика исследования (P3-5) без согласия |
| Закладки по заголовку или по номеру | `${discipline}:${number}` + миграция | `A-07`/`P1-2`: номер без дисциплины удаляет чужую закладку |

## 14. Что осознанно не делаем

- **Не переезжаем на фреймворк** и не вводим сборку — это решение проекта, а не долг.
- **Не делаем тёмную тему** (`U-12`) до стабилизации палитры: второй набор токенов поверх недоделанной системы удвоит работу.
- **Не делаем CMS/админку** (`O-01`), эссе и выгрузку (`R-07`–`R-12`) — другие этапы.
- **Не трогаем опрос** дальше общих компонентов (кнопки, поля, чекбокс): его методика заморожена.
- **Не переписываем контент кодом** — только черновики для автора.
- **Не гонимся за Lighthouse** — метрики берём из собственного харнесса, чтобы сравнивать «до/после» одинаково.

- **Плашка согласия не «в поток 56 px».** В поток её не поставить: тогда она видна только в конце страницы, а аналитика по закону включается лишь после выбора.
