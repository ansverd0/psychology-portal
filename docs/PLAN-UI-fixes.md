**Симптом:** после неверного ответа кнопка ведёт на страницу ошибки GitHub Pages (скриншот `image8`).

**Причина:** `js/quiz.js:164-172`

```js
const url = new URL(String(rawLink), window.location.origin);
```

А `link_url` в базе относительный: `sections.html?discipline=general-psych` (все 140 тестов, 3 варианта значения).
Итог: `https://ansverd0.github.io/sections.html?...` → 404.

**Что сделать:**

1. Резолвить от текущего документа: `new URL(String(rawLink), document.baseURI)`.
2. Проверить, что `sections-wiki.js:85-97` корректно открывает раздел по `?discipline=` (код есть, но `setTimeout(...,150)` — гонка с рендером; заменить на ожидание готовности данных/`requestAnimationFrame`).
3. *(Фаза 2, по желанию)* вести не только в раздел, но и в конкретную статью: добавить в `link_url` параметр `article=<id>` и обработку в `sections-wiki.js`.

**Проверка:** пройти тест → ошибиться → «Повторить тему конспекта» → открывается `/psychology-portal/sections.html?discipline=...` с активной папкой нужной дисциплины.

### UI-03 · Заголовки вопросов накладываются (ПК) — P0

**Симптом:** строки списка вопросов печатаются друг поверх друга, текст обрезан по высоте кнопки (видно на `image4` и `image11`).

**Причина:** `style.css:1165-1173` — колонка является flex-контейнером с ограничением высоты:

```css
.tickets-questions-column {
    display: flex; flex-direction: column;
    max-height: 60vh;           /* + переопределение 46vh в .nav-left */
    overflow-y: auto;
}
```

Кнопки (`question-nav-btn`, `folder-nav-btn`, `ticket-nav-btn`, `article-nav-btn`) — flex-элементы с `flex-shrink: 1` по умолчанию. Когда суммарная высота больше `max-height`, браузер **сжимает** кнопки ниже высоты контента, а текст из них вылезает.

**Что сделать:**

```css
.tickets-questions-column > *,
.tickets-folders-column > *,
.mobile-articles-container > * { flex: 0 0 auto; min-height: auto; }
```

Проверить также `#mobile-questions-list` (мобильный список) — тот же контейнерный тип.

**Проверка:** дисциплина с 8+ вопросами, ширины 1024/1280/1440 — заголовки не пересекаются, внутри колонки работает скролл.

### UI-04 · Вернуть 2 колонки навигации (ПК) — P1

**Причина:** `style.css:1013-1023` — `.nav-left` теперь одна колонка шириной 280px, в ней вертикально стоят и папки, и вопросы:

```css
.nav-left { display: flex; flex-direction: column; flex: 0 0 280px; }
```

**Что сделать:** на `min-width: 769px` перевести `.nav-left` в сетку «папки | вопросы»:

```css
@media (min-width: 769px) {
  .nav-left {
    display: grid;
    grid-template-columns: 240px 300px;
    gap: 12px;
    flex: 0 0 auto;
    width: auto;
    align-items: start;
  }
  .nav-left .nav-pane { width: 100%; }
}
```

Учесть общий бюджет ширины: сейчас `280 + 780 + 280 + 2×24 = 1388` при `max-width: 1600px`. После правки `240 + 300 + 12 + 780 + 280 + 2×24 ≈ 1660` → либо поднять `max-width` до 1680 (строка 1006), либо уменьшить контент до `flex-basis: 720px` (строка 1040). Заодно снять `max-height: 46vh` у `.nav-left .tickets-questions-column` (строка 1035) — колонки должны скроллиться независимо.

**Проверка:** 1024/1280/1440/1680 — папки слева, вопросы правее, ничего не заезжает на конспект; на 769–950 не ломается.

### UI-06 · Офлайн-плашка (index.html, моб.) — P1

**Симптом:** плашка шире экрана (обрезается справа) и накрывает кнопку «Главное меню» (`image3`).

**Причина:** `js/supabase-config.js:77`

```js
"position: fixed; top: 0; left: 0; width: 100%; padding: 10px; border-bottom: 2px solid ..."
```

`width: 100%` + `padding` + `border` без `box-sizing: border-box` → фактическая ширина `100% + 20px + 2px`. `position: fixed; top: 0; z-index: 9999` перекрывает шапку.

**Что сделать (вариант А, рекомендуется):** убрать из flow-перекрытия — плашка встаёт первым элементом `body` и раздвигает страницу:

```js
requestAnimationFrame(() => { document.body.classList.add('has-offline-banner'); });
```

```css
#offline-hub-notification {
  position: static; width: 100%; box-sizing: border-box;
  padding: 10px 16px calc(10px + env(safe-area-inset-top, 0px));
  ...
}
```

**Вариант Б (остаться fixed):** `box-sizing: border-box; left: 0; right: 0; width: auto;` + `body { padding-top: 56px; }` на время показа плашки.

**Проверка:** 360/390/430px, включая iPhone с «чёлкой» — плашка не выходит за экран, кнопка «Главное меню» полностью кликабельна.

## 5. Риски и подводные камни

1. **`CACHE_NAME`.** Самая частая причина «у меня не починилось» — старый SW отдаёт старый CSS. Поднимать версию в каждом релизе.
2. **Специфичность CSS.** В `style.css` уже есть правила с `!important` (`.tickets-folders-column { display: flex !important }`, строки 277-280 и 1245-1250) и каскад из 6 медиазапросов. Новые правила для `.nav-left` ставить после существующих блоков, иначе их перебьёт блок на строках 1349-1369 (769–1120px).
3. **`link_url` в базе.** Значения относительные (`sections.html?discipline=...`). Если планируется деплой в корень домена (не GitHub Pages) — резолвинг от `document.baseURI` работает в обоих случаях, так что правка безопасна.
4. **Закладки — localStorage, не БД.** Ключ `hub_bookmarks` трогать нельзя: у пользователей там уже сохранённые закладки. Модалка должна читать тот же массив.
5. **`max-height` vs `flex-shrink`.** Правка UI-03 лечит и мобильный список; после неё стоит перепроверить, что внутренний скролл остался (иначе колонка растянется на всю высоту и «уедет» sticky).
6. **Порядок колонок на ПК.** При переходе на grid порядок в разметке (`aside` папки → `aside` вопросы) совпадает с визуальным, `order` не нужен — но проверить на 769–950, где колонки узкие.
