## 1. Что изменилось в научной части

| | Старый план (`roadmap-diplom.md`) | Новый ВКР | Следствие для кода |
|---|---|---|---|
| Конструкты | тревожность (Прихожан) + мотивация (Гордеева) + саморегуляция (Моросанова) | мотивация ШАМ (Гордеева) + саморегуляция ССПМ (Моросанова) | тревожность, Спилберг, `initial_anxiety_tests` — вон |
| Гипотеза | высокая тревожность → избегание контроля / ригидная гиперкомпенсация | 4 квадранта по осям «общее время» × «регулярность сессий»; «оптимальная автономия» = лучшая саморегуляция + внутренняя мотивация | не корреляция «тревожность→паттерн», а типология: сначала признаки, потом кластеры |
| Входной срез | экспресс-опрос 6 вопросов | два полных опросника: ШАМ (28 пунктов, 7 шкал) + ССПМ | нужен полноценный бланковый модуль, а не 6 вопросов |
| Поведенческие данные | свой трекер событий | «цифровой след в Яндекс.Метрике»: хронометраж, индекс переключения, коэффициент своевременности, частота тестов, глубина теории | часть метрик Метрика не отдаёт по пользователю → нужен свой журнал + Метрика как зеркало |
| Статистика | K-means, Спирмен, U-Манна-Уитни | K-means (k=4), Краскел-Уоллис, Спирмен | U-Манна-Уитни убрать (сравниваем 4 группы, а не 2) |
| Продукт | личный профиль, геймификация, блокировки | однократное «Психолого-методическое руководство по развитию осознанной саморегуляции» для кураторов + блок самодиагностики | блокировки контента вредят экологической валидности — убрать |

**Главный вывод:** портал перестаёт быть «платформой с опросом при регистрации» и становится
**средой наблюдения**: он фиксирует естественное поведение, один раз собирает два опросника,
один раз — эссе, и всё это выгружается в таблицу «1 строка = 1 студент» для кластеризации.

## 2. Что в старом плане теперь неверно (правим точечно)

1. `Этап 2.1` — входной срез по Прихожан/Спилбергу: **удалить**.
2. `Этап 2.2` — блокировка контента до прохождения опроса: **удалить из исследования**.
   Принудительная блокировка меняет сессионный паттерн — то есть саму ось «регулярность».
   Опросник показывается один раз и не блокирует материалы.
3. `Этап 2.4` — «эссе по Леонтьеву»: оставить эссе, но назвать их по конструкту ВКР
   (эмоционально-смысловая регуляция), а критерии контент-анализа вывести из трёх теорий ВКР.
4. `Этап 4.10` — U-критерий Манна-Уитни: **заменить** на Краскела-Уоллиса + post-hoc (Данн, поправка Бенджамини-Хохберга).
5. `TECHCARD.md`, таблица БД: `initial_anxiety_tests` → `instrument_responses`; добавить `events`, `deadlines`.
6. `privacy.html` + галочка согласия: сейчас согласие покрывает «кэш, куки, метрики прогресса и эссе».
   Надо явно добавить **ответы на психологические опросники и журнал поведения** — это иное качество данных.

## 3. Следующие шаги разработки

Порядок жёсткий: каждый следующий шаг опирается на предыдущий. Оценки — в рабочих днях.

### Шаг A. Заморозка методики (R-01) — 1–2 дня, блокирует всё остальное

Без этого кода не пишем: любая правка формулировок ломает уже собранные данные.

- **A1. Опросники.** Зафиксировать: ШАМ — 28 утверждений, 7 шкал по 4, ответ 1–5; ССПМ —
  версия (30 или 98 пунктов) и ключи. Нужны исходные бланки и ключи от автора.
- **A2. Определения метрик цифрового следа** (формулы пишем до реализации):
  - `total_time_min` — сумма активного времени (вкладка видима) за окно;
  - сессия — разрыв активности > 30 мин начинает новую; `sessions_count`, `active_days`;
  - `regularity` = активные дни / дни окна (0…1) — ось «устойчивость регуляторного контура»;
  - `tab_switch_index` = переключения вкладки на 10 минут активного времени;
  - `deadline_coefficient` = доля сессий в интервале [дедлайн − 3 дня; дедлайн];
  - `tests_count`, `theory_depth` = уникальные статьи с dwell ≥ 60 с + средняя глубина прокрутки.
- **A3. Окно наблюдения** — 17.11.2026–29.01.2027 (включая зачёты и экзамены), дедлайны по группам заносятся в январе.
- **A4. Эссе.** 4 вопроса, окно сбора (январь, после сессии), категории контент-анализа
  и правила кодирования (2 кодировщика, согласие ≥ 0,7).
- **A5. Выгрузка и анализ.** Схема «1 строка = 1 студент», план: K-means k=4 (z-оценки,
  seed=42, n_init=50), проверка устойчивости методом Уорда, Краскел-Уоллис + Данн + BH,
  Спирмен, размеры эффекта.

**Готово, когда:** есть `docs/METHOD-FREEZE.md` на 3–5 страниц, согласованный с научруком.

### Шаг B. Схема БД и запись через RPC — 2–3 дня

- `instrument_responses` (`user_key`, `instrument`, `answers jsonb`, `scales jsonb`, `duration_ms`, `finished_at`);
- `events` (`user_key`, `session_id`, `page`, `event`, `ts`, `dwell_ms`, `scroll_pct`, `meta jsonb`) + индексы;
- `session_essays` дополнить (`prompt_no`, `text`, `word_count`, `codes jsonb`);
- `deadlines` (`discipline_id`, `kind`, `due_at`);
- `users_profiles`: `survey_done`, `essay_done`, `tests_completed_count`;
- RLS: anon — только INSERT через RPC с валидацией; SELECT своих строк; UPDATE/DELETE запрещены;
- миграции в `db/`, перед ними `node scripts/backup-db.mjs`.

**Готово, когда:** `node scripts/check-permissions.mjs` — все проверки PASS, включая новые таблицы.

### Шаг C. Бланковый модуль ШАМ + ССПМ — 2–3 дня

- отдельная страница `survey.html` (не модалка: 58+ пунктов в модалке неудобны на телефоне);
- блоки по 7–10 утверждений, прогресс, обязательность ответа, назад/вперёд;
- подсчёт шкал на клиенте по ключам (с реверс-пунктами), на сервер уходят и сырые ответы, и шкалы;
- одна запись на ключ: повторный вход показывает «пройдено» без повторного заполнения;
- валидация: минимальное время прохождения, honeypot, отсечение пустых.

**Готово, когда:** пройдены оба опросника под тестовым ключом, в БД 1 строка с корректными шкалами,
повторный вход не создаёт вторую.

### Шаг D. Трекер цифрового следа — 2–3 дня

- `js/tracker.js`: `session_id` (разрыв 30 мин), `page_view`, `dwell`, `scroll_max`,
  `visibility/blur` (переключение вкладки), `article_open`, `ticket_open`,
  `test_start/answer/complete`, `card_flip`, `search`;
- батчинг + `sendBeacon` на `pagehide`, офлайн-очередь с ретраем;
- зеркало в Метрику: `reachGoal` на ключевые события + `userParams` (уже есть) — чтобы данные
  сходились с Вебвизором;
- гости без ключа не пишутся; при отказе от аналитики трекер всё равно пишет в БД (это данные
  исследования, а не реклама), но в Метрику — нет.

**Готово, когда:** 5 минут работы на сайте дают события в `events` с dwell, scroll и переключениями;
закрытие вкладки не теряет последний батч.

### Шаг E. Окно эссе — 1–2 дня (код можно сделать сейчас, сбор — в январе)

- показ по дате/окну, 4 вопроса, одна отправка на ключ, сохранение;
- предупреждение «не указывайте ФИО» (свободный текст);
- выгрузка бланка для кодировщиков.

**Готово, когда:** эссе сохраняется, повторно не предлагается, в выгрузке есть text + codes.

### Шаг F. Выгрузка и анализ — 1–2 дня

- `scripts/export-research.mjs` (service_role) → `users.csv`, `events.csv`, `essays.csv` + словарь переменных;
- Python-конвейер: признаки → кластеризация → сравнение шкал → корреляции → графики
  (квадрантная диаграмма, боксплоты шкал по кластерам, теплокарта Спирмена);
- отчёт с таблицами для 3-й главы; всё воспроизводимо (seed, версия скрипта).

**Готово, когда:** на синтетических данных конвейер выдаёт те же кластеры при повторном запуске.

### Шаг G. Практический продукт — после результатов, 3–5 дней

- текст «Психолого-методического руководства по развитию осознанной саморегуляции
  в процессах самообразования»: цифровые ловушки, маркеры прокрастинации, копинг-стратегии;
- страница `guide.html` на портале + PDF для кураторов;
- блок самодиагностики по порогам, полученным в исследовании.

**Готово, когда:** руководство открывается с телефона, PDF отдаётся кураторам, самодиагностика считает по тем же порогам, что в главе 3.

### Шаг H. Пилот и запуск — 1–2 дня

- пилот на 5 участниках: пройти опросники, пожить на сайте, проверить события, выгрузку, шкалы;
- починить найденное;
- рассылка через кураторов/преподавателя, контроль воронки (сколько ключей → сколько опросников → сколько эссе);
- дальше — сбор: ноябрь–декабрь трек, январь эссе.

**Готово, когда:** пилот даёт полную строку выгрузки без ручных правок.

## 6. Риски

| Риск | Что делаем |
|---|---|
| Список групп не совпадёт с расписанием | дедлайны можно заводить и на уровне курса (`group_code` пустой) — метрика считается по более общей дате |
| Метрика не отдаёт переключения вкладок | свой трекер как основной источник, Метрика — сверка |
| 4 кластера на 60–70 человек | фиксируем k=4 и правило разметки квадрантов заранее; устойчивость проверяем Уордом; рапортуем размеры эффекта, а не только p |
| Гипотеза не подтвердится (квадранта нет) | это тоже результат: описываем эмпирическую типологию, гипотеза проверяется как «есть ли группа с профилем оптимальной автономии» |
| Эссе соберут мало | окно + напоминание куратора, эссе не блокирует доступ |
| Тексты эссе содержат ФИО | предупреждение в форме, чистка при кодировании |
